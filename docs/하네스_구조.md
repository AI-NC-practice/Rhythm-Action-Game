# 하네스 구조 설명서

각 파일이 하네스에서 어떤 역할을 하는지 정리한 문서입니다.

## 전체 흐름
```
[새 프로젝트 첫 세션] project-setup 스킬
   환경 확인 → 프로젝트 값 → GDD 함께 쓰기 → 작업 목록 승인 → "기획 확정" → harness/gdd.lock
   ↓
사용자: /run-tasks
   ↓
[run-tasks 스킬]  harness/.loop-active 생성 (루프 모드 켜기)
   ↓
tasks.json에서 다음 작업 선택 ──────────────────────────┐
   ↓                                                     │
type이 human? → 빌드+smoke-test 준비 → needs_user로 멈춤     │
   ↓                                                     │
작업 skill 절차 실행 (unity-feature / varco3d-asset / blender-tools)
   ↓                                                     │
자체 점검: unity-verify.ps1 (컴파일 + 테스트)              │
   ↓                                                     │
[evaluator 서브에이전트] 독립 평가 (다른 모델, 새 컨텍스트)  │
   ↓                                                     │
PASS → done + log + git commit + push ───────────────────┤
FAIL → 수정 후 재평가 (최대 3회) → 초과 시 failed로 멈춤    │
   ↓                                                     │
[Stop 훅] 남은 작업이 있으면 종료를 막고 루프 계속 ─────────┘
```

## 파일별 역할
| 파일 | 하네스 요소 | 역할 | 강제 여부 |
|---|---|---|---|
| `CLAUDE.md` | 컨텍스트 | 매 세션 자동으로 읽는 규칙 | 부탁 |
| `docs/GDD.md` | 컨텍스트 | 기획서, 모든 수치의 기준 (`GDD.template.md`에서 시작) | 확정 후 훅이 수정을 막음 |
| `harness/project.json` | 상태 관리 | 프로젝트 이름, 네임스페이스, Unity/Blender 경로, 설정 완료 여부 | - |
| `harness/gdd.lock` | 상태 관리 | 기획 확정 표시. 있으면 GDD 잠금 | 훅 |
| `harness/tasks.json` | 상태 관리 | 작업 목록, 완료 기준, 진행 상태 | - |
| `harness/asset_specs.json` | 상태 관리 | 에셋별 생성 명세, 리깅/애니메이션, 호출 횟수 | - |
| `harness/log.md` | 기록 | 작업 일지, 포인트 사용, 개선 제안 | - |
| `.claude/skills/project-setup/` | 스킬 | 첫 세션 절차 (환경, 기획, 작업 목록) | 부탁 |
| `.claude/skills/run-tasks/` | 스킬 | 메인 루프 절차 (`/run-tasks`) | 부탁 |
| `.claude/skills/unity-feature/` | 스킬 | Unity 구현 규칙 (테스트, 씬 코드 생성, 빌드, 애니메이션, 알려진 함정) | 부탁 |
| `.claude/skills/varco3d-asset/` | 스킬 | 에셋 생성 절차, 비용 제한, 리깅/애니메이션, Mixamo | 부탁 |
| `.claude/skills/blender-tools/` | 스킬 | (선택) 미리보기, GLB→FBX, 삼각형 줄이기 | 부탁 |
| `.claude/agents/evaluator.md` | 서브에이전트 | 독립 QA. 코드를 수정할 권한 없음, Sonnet 모델 | 도구 제한으로 강제 |
| `harness/scripts/unity-verify.ps1` | 검증 | 컴파일 + EditMode/PlayMode 테스트 | 기계적 판정 |
| `harness/scripts/unity-exec.ps1` | 도구 | 씬 생성, 빌드 같은 Editor 코드 실행 | - |
| `harness/scripts/smoke-test-build.ps1` | 검증 | 빌드한 exe를 화면 없이 실행해 로그 검사 | 기계적 판정 |
| `harness/scripts/download-asset.ps1` | 도구 | 생성된 GLB를 내려받아 저장 + 검사 | - |
| `harness/scripts/check-glb.ps1` | 검증 | GLB 삼각형 수와 용량 검사 | 기계적 판정 |
| `harness/scripts/extract-glb-textures.ps1` | 도구 | GLB 텍스처 꺼내기 (VARCO FBX용) | - |
| `harness/scripts/blender-run.ps1` | 도구 | (선택) Blender 스크립트 실행, 없으면 건너뜀 | - |
| `harness/scripts/hooks/session-start.ps1` | 훅 | 세션 시작 시 진행 상황/설정 필요 여부 알림 | 자동 실행 |
| `harness/scripts/hooks/protect-gdd.ps1` | 훅 | 기획 확정 후 GDD 수정 차단 | 강제 |
| `harness/scripts/hooks/stop-check.ps1` | 훅 | 루프 모드에서 남은 작업이 있으면 종료 차단 | 강제 |
| `harness/scripts/hooks/git-guard.ps1` | 훅 | 비밀 정보·20MB 초과 파일 차단, force push 차단 | 강제 |
| `harness/scripts/hooks/varco-guard.ps1` | 훅 | 전용 플로우만 사용, run_flow 횟수 제한, 기록 실패 시 차단 | 강제 |
| `harness/unity-templates/` | 시작 파일 | asmdef, GameConfig, BuildScript, Humanoid 임포트 예시 | - |
| `.gitignore` / `.gitattributes` | 저장소 규칙 | 올리지 않을 파일, 줄바꿈·바이너리 처리 (LFS 미사용) | 자동 |
| `.claude/settings.json` | 권한 + 훅 등록 | 위 훅 연결, 허용/금지 명령 | 강제 |

## 설계 포인트
1. **평가자 분리**: 구현한 Claude는 스스로 완료를 선언할 수 없습니다. 다른 모델(Sonnet)이 새 컨텍스트에서 작업 ID만 받아 평가합니다.
2. **기계적 검증 우선**: 테스트, 삼각형 수, 빌드 로그처럼 숫자나 로그로 판정할 수 있는 것은 스크립트가 판정합니다.
3. **씬을 코드로 생성**: Unity 씬 파일을 손으로 편집하지 않고 `SceneBuilder`가 만들기 때문에 언제든 같은 결과를 재현할 수 있습니다.
4. **사람 체크포인트**: 재미와 분위기는 사람만 판단할 수 있으므로 회색 상자 단계와 최종 단계에서 루프가 멈춥니다.
5. **빌드 점검**: 테스트를 다 통과해도 빌드에서만 생기는 문제가 있어서, 사람 확인 전에 exe를 화면 없이 실행해 봅니다.
6. **루프 가드**: Stop 훅은 루프 모드일 때만 동작하고, 진행 없이 반복되면 스스로 풀립니다(무한 루프 방지).
7. **비용 가드**: 이미지를 먼저 만들어 확인한 뒤에 3D를 생성하고, 에셋당 횟수와 전체 실행 횟수를 제한합니다. 훅은 기록에 실패하면 실행을 막습니다.
8. **기획 소유권**: 기획은 함께 쓰되, 확정은 사용자만 합니다. 확정 후에는 훅이 GDD를 지킵니다.
9. **저장소 보호**: 비밀 정보와 큰 파일은 커밋 단계에서, force push는 실행 단계에서 막습니다.
